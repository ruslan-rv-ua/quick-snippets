# PRD — QuickSnippets

## 1. Огляд продукту

### 1.1 Призначення та цінність

QuickSnippets — портативний десктопний додаток-лаунчер для операційної системи Windows, призначений для швидкого доступу до текстових сніпетів (фрагментів тексту) через нечіткий (fuzzy) пошук. Продукт вирішує проблему повторного набору або пошуку часто використовуваних текстових фрагментів — паролів, шаблонів повідомлень, адрес, серійних номерів, конфігураційних значень тощо.

Ключова цінність:
- **Миттєвий доступ** — глобальна гарячa клавіша викликає вікно з будь-якого застосунку; нечіткий пошук знаходить потрібний сніпет за декількома символами
- **Безпека** — підтримка шифрування окремих сніпетів з паролем; розшифрований вміст ніколи не відображається в інтерфейсі
- **Портативність** — усі дані (база сніпетів, файл налаштувань) зберігаються поруч з виконуваним файлом; не потрібна інсталяція
- **Доступність** — повна підтримка програм зчитування екрану (screen readers) та клавіатурної навігації

### 1.2 Цільова аудиторія та портрети користувачів

**Портрет 1: Розробник / системний адміністратор**
- Щодня використовує десятки команд, конфігураційних рядків, токенів API
- Потребує швидкого доступу до текстових фрагментів без перемикання контексту
- Цінує безпеку (зашифровані паролі та ключі)
- Працює переважно з клавіатурою

**Портрет 2: Офісний працівник**
- Часто вставляє шаблонні відповіді в листи, чат-повідомлення
- Потребує простого інтерфейсу без зайвих налаштувань
- Може потребувати зберігання конфіденційних даних (номери карток, паролі)

**Портрет 3: Користувач із вадами зору**
- Використовує програму зчитування екрану (screen reader)
- Потребує повної клавіатурної доступності
- Покладається на ARIA-анонси та послідовну навігацію

### 1.3 Ключові сценарії використання

| # | Сценарій | Опис |
|---|----------|------|
| S1 | Швидке копіювання | Користувач натискає глобальну гарячу клавішу → вводить кілька символів → натискає Enter → сніпет скопійовано в буфер обміну → вікно зникає |
| S2 | Копіювання зашифрованого сніпета | Як S1, але після Enter з'являється модальне вікно для введення пароля → після правильного пароля вміст копіюється в буфер |
| S3 | Створення нового сніпета | Ctrl+N → заповнення форми (назва, вміст, опціональний пароль) → збереження |
| S4 | Редагування сніпета | Вибір сніпета + Ctrl+E → зміна назви та/або вмісту (для незашифрованих) → збереження |
| S5 | Видалення сніпета | Вибір сніпета + Delete → підтвердження → видалення |
| S6 | Налаштування | Відкриття через трей або Ctrl+, → зміна теми, мови, автозапуску тощо |

## 2. Функціональні вимоги

### 2.1 Модуль: Сніпети (CRUD)

#### 2.1.1 Створення сніпета

- Система повинна дозволяти створювати новий сніпет із полями:
  - **Назва** (обов'язково): рядок від 3 до 50 символів
  - **Вміст** (обов'язково): текст від 1 до 65 536 символів
  - **Пароль** (опціонально): довільний рядок будь-якої довжини (мінімальна довжина не обмежена)
  - **Підтвердження пароля** (відображається завжди): повинно збігатися з полем «Пароль»
- Якщо пароль вказано — вміст шифрується перед збереженням; якщо ні — зберігається як відкритий текст
- Після успішного збереження:
  - Модальне вікно закривається
  - Показується toast-повідомлення «Збережено»
  - Список сніпетів оновлюється

#### 2.1.2 Читання / перегляд сніпетів

- Система повинна відображати список усіх сніпетів, відсортованих за датою останнього оновлення (найновіші — зверху)
- Кожен елемент списку відображає:
  - Назву сніпета
  - Іконку замка (🔒), якщо сніпет зашифрований
- Вміст сніпета **ніколи не відображається в списку**
- Для незашифрованих сніпетів: вміст доступний у модальному вікні редагування
- Для зашифрованих сніпетів: вміст **ніколи** не відображається в інтерфейсі

#### 2.1.3 Редагування сніпета

- Система повинна дозволяти редагувати існуючий сніпет:
  - **Назву** можна змінити завжди (валідація: 3–50 символів)
  - **Вміст** можна змінити тільки для **незашифрованих** сніпетів (валідація: 1–65 536 символів)
- Для зашифрованих сніпетів у вікні редагування замість поля вмісту відображається інформаційне повідомлення: «Вміст зашифровано і не може бути змінений»
- Після успішного збереження:
  - Модальне вікно закривається
  - Toast «Збережено»
  - Список оновлюється

#### 2.1.4 Видалення сніпета

- Система повинна дозволяти видалення будь-якого сніпета (як зашифрованого, так і відкритого)
- Перед видаленням — модальне вікно підтвердження з назвою сніпета та попередженням «Цю дію не можна скасувати»
- Видалення є остаточним (hard delete)
- Фокус за замовчуванням при відкритті вікна підтвердження — на кнопці «Скасувати» (щоб запобігти випадковому видаленню)
- Після успішного видалення:
  - Модальне вікно закривається
  - Toast «Видалено»
  - Список оновлюється

### 2.2 Модуль: Пошук

#### 2.2.1 Нечіткий (fuzzy) пошук

- Пошук здійснюється **тільки за назвами** сніпетів
- Алгоритм — нечіткий пошук (fuzzy matching): послідовність символів запиту повинна бути присутня в назві, але не обов'язково підряд
- Пошук є **регістронезалежним** (case-insensitive) — і запит, і назви приводяться до нижнього регістру перед порівнянням
- Пошуковий запит розбивається на слова (розділювач — пробіл); **всі слова** повинні знайти збіг у назві (AND-логіка)
  - Приклад: запит «pro prd» знаходить «prompt prd analize» та «prd add-req prompt»
- Для однословного запиту (без пробілів) додатково застосовується фолбек: кожна можлива 2-частинна розбивка слова перевіряється як мультитермовий AND-запит
  - Приклад: «proprd» → спробує «p»+«roprd», «pr»+«oprd», «pro»+«prd» тощо
  - Використовується **перша** успішна розбивка (а не найкраща за оцінкою)
  - Фолбек-результати отримують зниження оцінки -10 від базової
- Результати сортуються за оцінкою збігу (score) — від найвищої до найнижчої
- Позиції збіглих символів повертаються для візуального підсвічування

#### 2.2.2 Поведінка порожнього запиту

- При порожньому рядку пошуку система відображає **всі** сніпети, відсортовані за датою оновлення (найновіші зверху)
- Оцінка збігу (score) = 0, позиції збігу — порожній масив

#### 2.2.3 Debounce пошуку

- Пошуковий запит відправляється з затримкою 100 мс після останнього натискання клавіші (debounce)
- При непорожньому запиті з результатами — автоматично виділяється перший елемент списку

#### 2.2.4 Підсвічування збігів

- Символи в назві сніпета, які збіглися з запитом, підсвічуються кольором акценту (виділення жирним)
- Підсвічування базується на позиціях повернених сервером та/або простому підрядковому збігу як фолбеку

### 2.3 Модуль: Активація (копіювання в буфер обміну)

#### 2.3.1 Незашифрований сніпет

- При активації (Enter або клік) вміст копіюється в системний буфер обміну
- Копіювання відбувається на стороні сервера (бекенду); інтерфейс ніколи не отримує вміст
- Після копіювання:
  - Toast «Скопійовано»
  - Вікно ховається
  - Пошуковий рядок очищується
  - Список скидається до повного

#### 2.3.2 Зашифрований сніпет

- При активації відкривається модальне вікно введення пароля
- Користувач вводить пароль → система розшифровує на стороні сервера → копіює в буфер → обнуляє розшифровані дані в пам'яті
- **Розшифрований вміст НІКОЛИ не передається в інтерфейс** — інтерфейс отримує лише результат операції (успіх/помилка)
- Після успішного копіювання:
  - Toast «Скопійовано»
  - Вікно ховається
  - Модальне вікно пароля закривається
  - Пароль очищується з пам'яті
- При невірному паролі:
  - Повідомлення про помилку «Невірний пароль» під полем вводу
  - Поле пароля очищується
  - Фокус повертається на поле пароля
  - Вікно **не** ховається; можна спробувати ще раз
- При загальній помилці розшифрування:
  - Повідомлення «Помилка розшифрування»

### 2.4 Модуль: Шифрування

#### 2.4.1 Алгоритм

- Для генерації ключа з пароля використовується алгоритм PBKDF2-HMAC-SHA256 (KDF — Key Derivation Function):
  - Параметри: 100 000 ітерацій, унікальний salt на кожне шифрування, довжина ключа = 32 байти
- Шифрування — AES-256-GCM (authenticated encryption)
- Формат зашифрованих даних: `base64(salt[16 байт] || nonce[12 байт] || ciphertext || GCM-тег[16 байт])`
- Кожне шифрування генерує випадкові salt та nonce, тому два шифрування одного тексту дають різні результати
- Визначення невірного пароля: автентифікація GCM завершується помилкою
- Пароль **ніколи не зберігається** — ні у відкритому вигляді, ні у вигляді хешу

#### 2.4.2 Безпека пам'яті

- Після використання розшифровані дані та ключі повинні бути **гарантовано** обнулені в пам'яті (використовується механізм гарантованого очищення пам'яті, захищаючи від витоку через swap/dump)
- Пароль передається з інтерфейсу на сервер одноразово, використовується для KDF, після чого виходить зі scope

### 2.5 Модуль: Налаштування

#### 2.5.1 Параметри

| Параметр | Тип | За замовчуванням | Опис |
|----------|-----|-----------------|------|
| Тема | «dark» або «light» | «dark» | Кольорова тема інтерфейсу |
| Мова | «en», «uk» або порожній рядок | порожній (авто) | Мова інтерфейсу. Порожній рядок = автовизначення за системною локаллю |
| Запуск у треї | boolean | false | Якщо true — при запуску вікно приховане, тільки іконка в треї |
| Автозапуск | boolean | false | Якщо true — додаток автоматично запускається з операційною системою |
| Підтверджувати вихід | boolean | true | Якщо true — при спробі закрити вікно (Alt+F4 або ×) показується діалог підтвердження |
| Стан вікна | {x, y, width, height} | {100, 100, 680, 520} | Остання позиція та розмір вікна |

#### 2.5.2 Збереження

- Налаштування зберігаються в файлі поруч з виконуваним файлом (портативність)
- Формат збереження — структурований текст (наприклад, JSON)
- При зміні та збереженні налаштувань:
  - Тема та мова застосовуються негайно
  - «Автозапуск» змінюється негайно (реєстрація в системному автозапуску)
  - «Запуск у треї» набуває чинності після перезапуску
  - Стан вікна зберігається автоматично при переміщенні або зміні розміру та при завершенні роботи

#### 2.5.3 Обробка пошкодженого файлу налаштувань

- Якщо файл налаштувань існує, але містить невалідні дані:
  - Система показує нативний діалог ОС: «Файл settings.json пошкоджений. Скинути до стандартних налаштувань?» з кнопками «Так» / «Ні»
  - «Так» — файл перезаписується стандартними значеннями
  - «Ні» — додаток завершує роботу
- Якщо файл не існує — створюється автоматично зі стандартними значеннями

### 2.6 Модуль: Глобальна гаряча клавіша

- Комбінація: **Ctrl+Alt+Space**
- Поведінка: показує та фокусує головне вікно додатку з будь-якого контексту ОС
- Вікно відновлюється (з мінімізованого стану), виводиться на передній план та отримує фокус
- Якщо реєстрація гарячої клавіші не вдалася (комбінація зайнята іншим додатком):
  - Додаток продовжує працювати без гарячої клавіші
  - При першому показі вікна відображається toast-попередження: «Не вдалося зареєструвати глобальний хоткей Ctrl+Alt+Space. Застосунок працює, але виклик через хоткей недоступний»
  - Toast-попередження показується 5 секунд (замість стандартних 2 секунд)
  - Текст: «Не вдалось зареєструвати глобальний хоткей Ctrl+Alt+Space. Застосунок працює, але виклик через хоткей недоступний»

### 2.7 Модуль: Системний трей

- Додаток відображає іконку в системному треї Windows
- Іконка — мінімалістична піктограма документа з лініями тексту (16×16 пікселів), генерується програмно при старті додатку (не зовнішній файл)
- Tooltip іконки: «QuickSnippets»
- **Клік лівою кнопкою** — показує та фокусує головне вікно
- **Клік правою кнопкою** — контекстне меню:

| Пункт меню | Дія |
|------------|-----|
| Показати | Показати та сфокусувати вікно |
| Новий сніпет | Показати вікно + відкрити модальне вікно створення сніпета |
| Налаштування | Показати вікно + відкрити модальне вікно налаштувань |
| — (роздільник) | — |
| Вихід | Завершити роботу додатку |

- Пункти меню трею локалізовані відповідно до мови з налаштувань (визначається одноразово при старті додатку і не змінюється до перезапуску)
- Нативні діалоги ОС (пошкоджені файли) використовують мову, визначену ще до завантаження налаштувань (автовизначення з локалі ОС), щоб коректно показувати повідомлення навіть коли сам файл налаштувань пошкоджений

### 2.8 Модуль: Єдиний екземпляр (Single Instance)

- Система повинна гарантувати, що одночасно працює лише один екземпляр додатку
- При спробі запустити другий екземпляр — ѩн завершується, а **існуюче вікно отримує фокус** (відновлюється з трею і виводиться на передній план)

### 2.9 Модуль: Автозапуск

- Якщо увімкнено — додаток реєструється в системному автозапуску Windows (реєстр поточного користувача: `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`)
- Якщо вимкнено — реєстрація видаляється
- Видалення неіснуючого запису не є помилкою

### 2.10 Модуль: Поведінка вікна

#### 2.10.1 Розміри

- Розмір за замовчуванням: 680×520 пікселів
- Мінімальний розмір: 480×320 пікселів
- Позиція та розмір зберігаються між сесіями
- Вікно **відображається** в панелі завдань Windows (не приховане)

#### 2.10.2 Відновлення стану

- При запуску вікно відновлює збережену позицію та розмір
- Захист від «вікна за межами екрану»: якщо збережена позиція X < -1000 або Y < -1000 або X > 10000 або Y > 10000 — скидається до {100, 100}
- Якщо збережені розміри менші за мінімальні — використовуються розміри за замовчуванням

#### 2.10.3 Приховування вікна

Вікно ховається (не закривається) при:
- **Escape** з порожнім рядком пошуку
- **Успішній активації** сніпета (Enter/клік + копіювання)
- **Втраті фокусу** вікном (клік за межами вікна)
- **Кнопці ×** або **Alt+F4** (залежно від налаштування «Підтверджувати вихід»):
  - Якщо підтвердження увімкнено → модальне вікно «Ви дійсно хочете вийти з програми?» з кнопками «Скасувати» та «Вийти»
    - «Вийти» → завершення додатку
    - «Скасувати» → закриття модального вікна, приховування основного вікна
  - Якщо підтвердження вимкнено → додаток завершує роботу

#### 2.10.4 Скидання стану при приховуванні

При кожному явному приховуванні вікна (Escape, успішна активація, кнопка «Скасувати» у діалозі виходу):
- Пошуковий рядок очищується
- Активний індекс скидається до -1 (нічого не виділено)
- Список сніпетів оновлюється до повного (як при порожньому запиті)
- Усі модальні вікна закриваються
- Пароль (якщо був введений) очищується

#### 2.10.5 Втрата фокусу (blur)

- Приховування вікна при втраті фокусу виконується автоматично на рівні ОС
- На рівні інтерфейсу при втраті фокусу виконується лише **часткове скидання стану**:
  - Пошуковий рядок очищується
  - Активний індекс скидається
  - Список оновлюється
  - Якщо модальне вікно пароля було відкрите — воно закривається, пароль очищується
  - **Інші модальні вікна** (створення, редагування, видалення, налаштування, підтвердження виходу) **НЕ закриваються** автоматично при blur — лише вікно пароля, з міркувань безпеки

#### 2.10.6 Контекстне меню браузера

- Стандартне контекстне меню (правий клік) вимкнено по всьому вікну

## 3. Вимоги до інтерфейсу

### 3.1 Архітектура навігації

Додаток має **один екран** (головне вікно) з модальними вікнами:

```
Головне вікно
├── Зона пошуку (SearchBox)
├── Список сніпетів (SnippetList)
│   └── Елемент сніпета (SnippetItem) × N
├── [Модальне] Створення сніпета
├── [Модальне] Редагування сніпета
├── [Модальне] Підтвердження видалення
├── [Модальне] Введення пароля
├── [Модальне] Підтвердження виходу
├── [Модальне] Налаштування
└── Toast-повідомлення
```

### 3.2 Зона пошуку (SearchBox)

#### Layout
- Розташована у верхній частині вікна
- Містить одне текстове поле вводу типу «search»
- Внутрішні відступи: 14px зверху/знизу, 18px зліва/зправа
- Розділена від списку нижнім бордером та тінню `--shadow-sm` для візуального відокремлення (z-index: 10)

#### Поведінка
- Фокус **завжди** залишається на полі пошуку (Tab не переміщує фокус)
- При введенні тексту:
  - Dispatch події input з затримкою (debounce 100 мс)
  - Результати оновлюються в списку нижче
- Клавіші:
  - **ArrowDown** — виділити наступний елемент у списку (зупиняється на останньому, **не** обертається на початок)
  - **ArrowUp** — виділити попередній елемент (зупиняється на першому, **не** обертається на кінець)
  - Якщо не виділено жоден елемент — як ArrowDown, так і ArrowUp виділяють **перший** елемент списку
  - **Enter** — активувати виділений сніпет
  - **Escape** (непорожній запит) — очистити запит; подія НЕ поширюється далі
  - **Escape** (порожній запит) — подія поширюється до глобального обробника → вікно ховається
  - **Tab** — заблоковано (preventDefault)

#### Стани поля вводу
- **Default**: фон `--color-bg-input`, бордер прозорий
- **Focus**: фон `--color-bg`, бордер `--color-accent`, зовнішнє кільце фокусу 3px `--color-focus-ring`

#### ARIA-атрибути
- `aria-label`: «Пошук сніпетів» (локалізовано)
- `aria-activedescendant`: вказує на ID виділеного елемента списку
- `autocomplete="off"`, `spellcheck="false"`

### 3.3 Список сніпетів (SnippetList)

#### Layout
- Займає весь простір під зоною пошуку
- Вертикальний скролінг (overflow-y: auto)
- Внутрішній відступ: 8px зверху/знизу

#### Поведінка
- При зміні активного індексу активний елемент автоматично прокручується у видиму зону (`scrollIntoView: nearest`)
- Клік по елементу — активація сніпета

#### Порожні стани
- **Немає сніпетів (порожня база)**: «Немає сніпетів. Натисніть Ctrl+N або Insert щоб створити.» (центровано, приглушений колір)
- **Нічого не знайдено (пошук без результатів)**: «Нічого не знайдено.» (центровано, приглушений колір)

#### ARIA: live region
- Полite live region оголошує кількість знайдених результатів із затримкою ~200 мс після останнього оновлення
- Формат: «{N} сніпетів. {назва першого}»
- Затримка потрібна, щоб не накладатися на aria-activedescendant анонс

### 3.4 Елемент сніпета (SnippetItem)

#### Layout
- Горизонтальний flex-контейнер
- Зліва: іконка замка 🔒 (тільки для зашифрованих; декоративна, `aria-hidden="true"`)
- Справа: назва сніпета з підсвічуванням збігів
- Внутрішні відступи: 12px зверху/знизу, 18px зліва/зправа
- Зовнішні відступи: 2px зверху/знизу, 8px зліва/зправа
- Довгі назви обрізаються з еліпсисом (text-overflow: ellipsis)

#### Стани
- **Default**: фон `--color-bg-item`
- **Active (виділений)**: фон `--color-bg-active`, зсув вправо на 2px (translateX)
- **Hover**: фон `--color-bg-active`

#### Підсвічування збігів
- Збіглі символи виділяються тегом `<mark>`: прозорий фон, колір тексту `--color-match-highlight`, жирний шрифт (font-weight: 600)
- `<mark>` має `aria-hidden="true"` (підсвічування — лише візуальне)

#### ARIA
- Кожен елемент має `id="snippet-{id}"` (для aria-activedescendant)
- `aria-label`: назва сніпета; для зашифрованих — «{назва}, зашифрований»

### 3.5 Модальне вікно: Створення сніпета

#### Layout
- Ширина: 480px (max: 100vw - 32px)
- Поля:
  1. **Заголовок** (текстове поле, maxlength=50, обов'язкове)
  2. **Вміст** (textarea, maxlength=65536, 5 рядків, обов'язкове)
  3. **Пароль** (password, опціональне)
  4. **Підтвердження пароля** (password)
- Кнопки: «Скасувати» (secondary), «Зберегти» (primary)

#### Поведінка
- При відкритті: всі поля очищуються, фокус на полі «Заголовок»
- Валідація виконується **тільки при натисканні «Зберегти»** (немає інлайн-валідації в реальному часі):
  - Заголовок: 3–50 символів → помилка «Заголовок: від 3 до 50 символів»
  - Вміст: 1–65 536 символів → помилка «Вміст: від 1 до 65536 символів»
  - Паролі не збігаються → помилка «Паролі не співпадають»
- При помилці: фокус переміщується на перше невалідне поле
- Закриття: кнопка «Скасувати», Escape, клік по оверлею
- Швидке збереження: Ctrl+Enter

> **Примітка:** Захист від подвійного збереження (disabled кнопка під час асинхронної операції) реалізовано в модальних вікнах пароля та налаштувань. У модальних вікнах створення та редагування сніпета цей захист відсутній — операції збереження виконуються достатньо швидко, але може бути додано за потреби

#### ARIA
- `role="dialog"`, `aria-modal="true"`, `aria-labelledby` → заголовок модального вікна
- Assertive live region для помилок валідації
- Невалідні поля: `aria-invalid="true"`, `aria-describedby` → ID повідомлення про помилку
- Обов'язкові поля: `aria-required="true"`
- Помилка: `role="alert"` на елементі з текстом помилки

### 3.6 Модальне вікно: Редагування сніпета

#### Layout та поведінка
- Аналогічно створенню, за винятком:
  - Немає полів пароля
  - Якщо сніпет зашифрований — замість textarea відображається інформаційне повідомлення:
    - «Вміст зашифровано і не може бути змінений»
    - Стиль: курсив, фон `--color-bg-input`, ліва рамка кольору `--color-icon-lock`
- При відкритті: поля заповнюються поточними значеннями
- Валідація: заголовок (3–50 символів), вміст (1–65 536 символів, тільки для незашифрованих)

### 3.7 Модальне вікно: Підтвердження видалення

#### Layout
- Заголовок: «Видалити сніпет?»
- Назва сніпета у «лапках» з лівою рамкою кольору `--color-destructive`
- Попередження: «Цю дію не можна скасувати.»
- Кнопки: «Скасувати» (secondary, фокус за замовчуванням), «Видалити» (destructive — червоний)

#### ARIA
- `role="dialog"`, `aria-modal="true"`

### 3.8 Модальне вікно: Введення пароля

#### Layout
- Ширина: 400px
- Заголовок: «Введіть пароль»
- Підзаголовок: «Розшифрувати «{назва сніпета}»» з лівою рамкою кольору `--color-icon-lock`
- Поле: пароль (password, обов'язкове)
- Кнопки: «Скасувати» (secondary), «Копіювати» (primary)
- Під час розшифрування: кнопка показує «Розшифрування…», обидві кнопки disabled, поле вводу також disabled

#### Поведінка
- При відкритті: фокус на полі пароля; попередній пароль завжди очищений
- Enter → спроба розшифрування
- Escape → закриття
- Помилки:
  - Порожній пароль: «Введіть пароль»
  - Невірний пароль: «Невірний пароль» (поле очищується, фокус повертається)
  - Загальна помилка: «Помилка розшифрування»
- При закритті будь-яким способом — пароль очищується з пам'яті

### 3.9 Модальне вікно: Підтвердження виходу

#### Layout
- Заголовок: «QuickSnippets — Підтвердження»
- Повідомлення: «Ви дійсно хочете вийти з програми?»
- Кнопки: «Скасувати» (secondary, фокус за замовчуванням), «Вийти» (primary)

#### Поведінка
- Escape → скасувати (сховати вікно)
- Enter → підтвердити (вийти)
- «Скасувати» → закрити модальне вікно + сховати основне вікно
- «Вийти» → завершити роботу додатку

> **Важливо:** На відміну від модального вікна підтвердження виходу, у модальному вікні **підтвердження видалення** клавіша Enter **не підтверджує** дію — це захист від випадкового видалення.

### 3.10 Модальне вікно: Налаштування

#### Layout
- Заголовок: «Налаштування»
- Поля:
  1. **Тема**: група кнопок «Темна» / «Світла» (toggle)
  2. **Мова**: випадаючий список — «Авто (системна)», «English», «Українська»
  3. **Запуск у треї**: чекбокс
  4. **Автозапуск з Windows**: чекбокс
  5. **Підтверджувати вихід**: чекбокс
- Підказка: «Деякі зміни набудуть чинності після перезапуску.»
- Кнопки: «Скасувати» (secondary), «Зберегти» (primary)
- Стан завантаження: «…» поки налаштування завантажуються (`aria-live="polite"`, `aria-busy="true"`)

#### Поведінка
- При відкритті: асинхронне завантаження поточних налаштувань
- При збереженні: тема та мова застосовуються негайно, решта — відповідно до 2.5.2
- Кнопка «Зберегти» стає disabled під час асинхронного збереження (захист від подвійного натиску)
- Escape → закрити без збереження
- Ctrl+Enter → швидке збереження

#### ARIA
- `role="dialog"`, `aria-modal="true"`
- Група кнопок теми: `role="group"`, `aria-pressed` на кожній кнопці

### 3.11 Загальна оверлейна обгортка модальних вікон (ModalOverlay)

- Напівпрозорий чорний фон (rgba(0, 0, 0, 0.6))
- Модальне вікно центроване вертикально та горизонтально
- Анімація появи: fade-in 150 мс
- Клік по оверлею (поза модальним вікном) → закриття
- **Пастка фокусу** (focus trap): Tab та Shift+Tab циклічно переміщують фокус між фокусовними елементами всередині модального вікна
- При відкритті: попередній активний елемент зберігається
- При закритті: фокус повертається на попередній елемент

### 3.12 Toast-повідомлення

#### Layout
- Позиція: нижній правий кут (fixed), 16px від краю
- Стек: вертикальний, gap 8px (нові toast додаються знизу)
- Стиль: фон `--color-bg-active`, бордер `--color-border`, тінь `--shadow-md`
- Типи:
  - **success**: зелений бордер (#4caf50)
  - **warning**: помаранчевий бордер (#ff9800)
  - **error**: червоний бордер (`--color-destructive`)
  - **info**: стандартний бордер

#### Поведінка
- Тривалість: 2 секунди (за замовчуванням), 5 секунд для попередження про гарячу клавішу
- Анімація появи: slide-in знизу 150 мс
- Анімація зникнення: fade-out 300 мс (починається за 2 секунди)
- Після зникнення анімації — елемент видаляється з DOM
- Не інтерактивні (pointer-events: none)

#### ARIA
- Контейнер: `aria-live="polite"`, `aria-atomic="true"`

## 4. Потоки користувача

### 4.1 Потік: Швидке копіювання незашифрованого сніпета

1. Користувач натискає **Ctrl+Alt+Space** (глобальна гаряча клавіша)
2. Головне вікно з'являється, фокус — на полі пошуку
3. Користувач вводить кілька символів
4. Після 100 мс debounce — список фільтрується, перший елемент виділяється
5. Користувач натискає **ArrowDown/ArrowUp** для навігації (опціонально)
6. Користувач натискає **Enter**
7. Вміст копіюється в системний буфер обміну (на стороні бекенду)
8. Toast «Скопійовано» з'являється на 2 секунди
9. Вікно ховається; пошук очищується; список скидається

### 4.2 Потік: Копіювання зашифрованого сніпета

1. Кроки 1–5 з потоку 4.1
2. Користувач натискає **Enter** на зашифрованому сніпеті (відмічений 🔒)
3. З'являється модальне вікно «Введіть пароль» з фокусом на полі пароля
4. Користувач вводить пароль, натискає **Enter**
5. Система розшифровує вміст на стороні бекенду
6. **Успіх**: вміст копіюється в буфер → toast «Скопійовано» → вікно ховається
7. **Невірний пароль**: повідомлення «Невірний пароль», поле очищується, фокус повертається на поле → користувач може спробувати ще раз

### 4.3 Потік: Створення сніпета

1. Користувач натискає **Ctrl+N** або **Insert** (або через меню трею)
2. Модальне вікно створення відкривається, фокус — на полі «Заголовок»
3. Користувач заповнює поля
4. (Опціонально) Вводить пароль та його підтвердження
5. Натискає **Зберегти** або **Ctrl+Enter**
6. **Валідація пройдена**: сніпет зберігається → toast «Збережено» → список оновлюється
7. **Валідація не пройдена**: помилки відображаються під відповідними полями, фокус переміщується на перше невалідне поле

### 4.4 Потік: Редагування сніпета

1. Користувач виділяє сніпет у списку
2. Натискає **Ctrl+E**
3. Модальне вікно редагування відкривається з поточними даними
4. Для незашифрованого: можна змінити назву та вміст
5. Для зашифрованого: можна змінити тільки назву; поле вмісту замінено на інформаційне повідомлення
6. Натискає «Зберегти» → перевірка → збереження → toast → оновлення списку

### 4.5 Потік: Видалення сніпета

1. Користувач виділяє сніпет у списку
2. Натискає **Delete**
3. Модальне вікно підтвердження видалення з'являється; фокус — на «Скасувати»
4. Користувач натискає «Видалити» → сніпет видалено → toast → список оновлюється
5. Або натискає «Скасувати» / Escape → повернення до списку

### 4.6 Потік: Налаштування

1. Користувач натискає **Ctrl+,** або обирає «Налаштування» в меню трею
2. Модальне вікно налаштувань відкривається; поточні значення завантажуються асинхронно
3. Показується індикатор завантаження «…» поки дані не завантажені
4. Користувач змінює потрібні параметри
5. Натискає «Зберегти» → налаштування зберігаються → тема/мова змінюються негайно → toast «Збережено»

### 4.7 Потік: Перший запуск

1. Файл налаштувань не існує → створюється зі стандартними значеннями
2. Мова визначається автоматично за системною локаллю Windows:
   - Якщо системна мова починається на «uk» → українська
   - Інакше → англійська
3. Файл бази даних не існує → створюється автоматично (порожня база)
4. Вікно з'являється з порожнім списком: «Немає сніпетів. Натисніть Ctrl+N або Insert щоб створити.»
5. Реєструється глобальна гаряча клавіша; якщо не вдалося — toast-попередження

### 4.8 Потік: Закриття вікна (×, Alt+F4)

#### Варіант A: підтвердження увімкнено (confirm_on_close = true)
1. Користувач натискає × або Alt+F4
2. Закриття вікна перехоплюється
3. З'являється модальне вікно підтвердження
4. «Вийти» → додаток завершується
5. «Скасувати» → модальне вікно закривається, основне вікно ховається

#### Варіант B: підтвердження вимкнено (confirm_on_close = false)
1. Користувач натискає × або Alt+F4
2. Додаток завершує роботу негайно

### 4.9 Альтернативні та помилкові сценарії

| Сценарій | Обробка |
|----------|---------|
| Пошук не знаходить результатів | Відображається «Нічого не знайдено.» |
| Натискання Enter без виділеного сніпета | Ігнорується |
| Будь-які гарячі клавіші під час відкритого модального вікна | Ігноруються (крім Escape, Enter/Ctrl+Enter у відповідних модальних) |
| Ctrl+E без виділеного сніпета | Ігнорується |
| Delete без виділеного сніпета | Ігнорується |
| Помилка збереження сніпета | Помилка логується в консоль |
| Помилка завантаження налаштувань (для модального вікна) | Модальне вікно закривається |
| Файл бази даних пошкоджений | Нативний діалог ОС: пропозиція скинути базу. «Так» → база перестворюється (всі дані втрачено). «Ні» → додаток завершується |
| Помилка завантаження налаштувань під час закриття вікна | Система за замовчуванням показує діалог підтвердження виходу |
| Файл налаштувань пошкоджений | Нативний діалог ОС: пропозиція скинути налаштування. «Так» → стандартні значення. «Ні» → додаток завершується |
| Глобальна гаряча клавіша зайнята | Toast-попередження на 5 секунд, додаток працює без хоткея |

### 5.2 Правила валідації

| Поле | Правило | Повідомлення про помилку |
|------|---------|--------------------------|
| title (створення/edit) | 3 ≤ length ≤ 50 | «Заголовок: від 3 до 50 символів» |
| content (створення/edit) | 1 ≤ length ≤ 65 536 | «Вміст: від 1 до 65536 символів» |
| password confirmation | Збігається з password | «Паролі не співпадають» |
| password (decrypt) | Непорожній | «Введіть пароль» |

**Валідація на рівні бази:**
- title: CHECK(length(title) >= 3 AND length(title) <= 50)
- content: CHECK(length(content) <= 65536)

### 5.3 Порожні стани (Empty States)

| Контекст | Повідомлення |
|----------|-------------|
| Порожня база, порожній запит | «Немає сніпетів. Натисніть Ctrl+N або Insert щоб створити.» |
| Пошук без результатів | «Нічого не знайдено.» |

### 5.4 Збереження даних

- **Сніпети**: локальна вбудована реляційна база даних, файл зберігається поруч з виконуваним файлом
- **Налаштування**: структурований текстовий файл (JSON-подібний) поруч з виконуваним файлом
- **Кешування**: не використовується — усі запити виконуються напряму до бази
- **Синхронізація**: не підтримується — додаток суто локальний
- Конкурентний доступ: обмеження на один запис одночасно (single writer)
- База даних повинна використовувати журнальний режим із покращеною продуктивністю паралельного читання
- Автоматичне очікування до 5000 мс при конкурентному доступі

## 6. Інтеграції та API

### 6.1 Внутрішні API (IPC)

Взаємодія між інтерфейсом та бекендом здійснюється через IPC (Inter-Process Communication). Інтерфейс викликає методи бекенду і отримує результати.

| Метод | Параметри | Результат | Опис |
|-------|-----------|-----------|------|
| `search_snippets` | query: рядок | масив SearchResult | Порожній запит → всі сніпети |
| `get_snippet_by_id` | id: ціле | SnippetView | Для незашифрованих: включає content. Для зашифрованих: content порожній |
| `create_snippet` | title, content, password: рядки | помилка або нічого | password="" → незашифрований |
| `activate_snippet` | id: ціле, password: рядок | помилка або нічого | Розшифровує + копіює. password="" для незашифрованих |
| `update_snippet` | id: ціле, title, content: рядки | помилка або нічого | Для зашифрованих content ігнорується, зберігається існуючий blob |
| `delete_snippet` | id: ціле | помилка або нічого | Безповоротне видалення |
| `get_settings` | — | структура Settings | Поточні налаштування |
| `save_settings` | структура Settings | помилка або нічого | Зберігає + застосовує автозапуск. **Завжди перезаписує WindowState поточною геометрією вікна**, щоб запобігти перезапису актуального стану застарілими значеннями при збереженні з інших контекстів (наприклад, зміна теми) |
| `get_pending_notification` | — | рядок | Одноразове попередження при старті (очищується після першого виклику) |
| `quit_app` | — | — | Завершує додаток |

### 6.2 Події (Events)

Бекенд → Інтерфейс:

| Подія | Тригер | Дія інтерфейсу |
|-------|--------|---------------|
| tray:create-snippet | Пункт «Новий сніпет» у меню трею | Відкрити модальне вікно створення |
| tray:open-settings | Пункт «Налаштування» у меню трею | Відкрити модальне вікно налаштувань |
| window:close-request | ×/Alt+F4 при confirm_on_close=true | Відкрити модальне вікно підтвердження |

### 6.3 Зовнішні сервіси

Додаток **не використовує** жодних зовнішніх API, мережевих з'єднань чи хмарних сервісів. Усі дані зберігаються та обробляються виключно локально.

## 7. Автентифікація та авторизація

### 7.1 Загальна модель

Додаток **не має системи автентифікації користувачів**. Немає облікових записів, логінів чи ролей. Будь-хто, хто має фізичний доступ до комп'ютера з запущеним додатком, може переглядати, створювати, редагувати та видаляти сніпети.

### 7.2 Захист окремих сніпетів

- Кожен сніпет може бути зашифрований індивідуальним паролем при створенні
- Для доступу до вмісту зашифрованого сніпета потрібен правильний пароль
- Пароль запитується щоразу при активації зашифрованого сніпета (пароль не зберігається і не кешується)
- Без правильного пароля неможливо:
  - Переглянути вміст зашифрованого сніпета
  - Скопіювати його в буфер обміну
- Без пароля **можливо**:
  - Бачити назву зашифрованого сніпета в списку
  - Бачити іконку замка
  - Змінити назву зашифрованого сніпета
  - Видалити зашифрований сніпет

## 8. Нефункціональні вимоги

### 8.1 Продуктивність

| Метрика | Вимога |
|---------|--------|
| Час показу вікна (гаряча клавіша → render) | < 300 мс (суб'єктивно миттєво) |
| Час пошуку | < 50 мс для 1000 сніпетів |
| Debounce пошуку | 100 мс |
| Час шифрування (PBKDF2-HMAC-SHA256, 100k іт.) | ~10–50 мс (залежить від обладнання) |
| Час копіювання в буфер | < 10 мс |
| Розмір бази даних | Необмежений (практично — до тисяч сніпетів) |
| Максимальний вміст одного сніпета | 65 536 символів |

### 8.2 Безпека

#### Критичні вимоги (порушення = баг)

1. **Розшифрований вміст НІКОЛИ не передається в інтерфейс.** Бекенд розшифровує → копіює в буфер обміну → обнуляє пам'ять. Інтерфейс отримує лише success/error
2. **Пароль** передається з інтерфейсу на бекенд одноразово, використовується для KDF, після чого має бути прибраний зі scope. Бекенд не повертає і не зберігає пароль
3. **Копіювання в буфер обміну** відбувається виключно на стороні бекенду. Інтерфейс не має доступу до вмісту зашифрованих сніпетів
4. **Пароль не зберігається** ніде — ні в базі, ні в налаштуваннях, ні в пам'яті між операціями

#### Додаткові вимоги

5. Кожне шифрування використовує унікальні випадкові salt (16 байт) та nonce (12 байт)
6. Розшифровані дані та ключі **гарантовано** обнуляються в пам'яті після використання (захист від витоку через swap/dump)
7. Файли даних (база, налаштування) зберігаються без додаткового захисту — безпека конфіденційних даних забезпечується шифруванням на рівні окремих сніпетів
8. Поле `content` сніпета виключене з серіалізації при передачі через IPC (вміст не включається в автоматичні відповіді бекенду). Для зашифрованих сніпетів вміст доступний тільки через метод `activate_snippet`, який виконує розшифрування та копіювання на стороні бекенду

### 8.3 Доступність (Accessibility)

#### ARIA

- Кореневий елемент додатку має `role="application"` для коректної роботи screen readers (примушує вийти з «режиму перегляду» / browse mode)
- Пошукове поле має `aria-activedescendant` для оголошення активного елемента списку
- Елементи списку мають унікальні `id` та `aria-label` (включаючи тип «зашифрований» для encrypted)
- Модальні вікна: `role="dialog"`, `aria-modal="true"`, `aria-labelledby`
- Поля форм: `aria-required`, `aria-invalid`, `aria-describedby` для повідомлень про помилки
- Помилки валідації: `role="alert"` для негайного оголошення
- Декоративні елементи (іконки замка, підсвічування): `aria-hidden="true"`

#### Live Regions

- **Polite** live region для кількості результатів пошуку (з затримкою ~200 мс)
- **Assertive** live region для on-demand оголошень (Ctrl+Shift+Space)
- **Polite** live region для toast-повідомлень
- **Assertive** live region для помилок валідації в модальних вікнах

#### Клавіатурна навігація

| Контекст | Клавіша | Дія |
|----------|---------|-----|
| Головне вікно | Ctrl+Alt+Space | Показати вікно (глобально) |
| Пошук | ArrowDown/Up | Навігація по списку |
| Пошук | Enter | Активувати сніпет |
| Пошук | Escape (непорожній) | Очистити запит |

| Головне вікно | Ctrl+E | Редагувати виділений сніпет |
| Головне вікно | Delete | Видалити виділений сніпет |
| Головне вікно | Ctrl+Shift+T | Перемкнути тему |

#### Screen Reader: On-demand оголошення (Ctrl+Shift+Space)

- При натисканні Ctrl+Shift+Space система оголошує поточний виділений елемент:
  - Формат: «{назва}, {тип}, {номер} з {загальна кількість}»
  - Тип: «звичайний» або «зашифрований»
- Якщо нічого не виділено: «Нічого не виділено»
- Використовує assertive live region для негайного оголошення
- При повторному натисканні на тому ж елементі: live region спочатку очищується, потім через 50 мс заповнюється (для повторного тригеру)

#### Примусова побудова дерева доступності

- Вбудований браузерний компонент повинен бути налаштований на примусову побудову дерева доступності при запуску
- Це необхідно, тому що автоматичне визначення screen reader всередині вбудованого браузера ненадійне

#### Focus-visible

- Усі інтерактивні елементи мають видимий індикатор фокусу при клавіатурній навігації: 2px solid `--color-accent`, offset 2px
- Звичайний `:focus` без видимого контуру (для мишки)

## 11. Відкриті питання

1. **Обмеження кількості сніпетів**: Не визначено максимальну кількість сніпетів. Система теоретично може стати повільною при тисячах записів, але формального ліміту немає.

2. **Зміна пароля зашифрованого сніпета**: Відсутня функціональність зміни пароля або повторного шифрування. Для зміни пароля потрібно видалити сніпет та створити новий.

3. **Зміна вмісту зашифрованого сніпета**: Неможлива через інтерфейс. Для зміни вмісту потрібно видалити та створити заново.

4. **Експорт/імпорт сніпетів**: Функціональність відсутня. Перенесення даних можливе лише шляхом копіювання файлу бази даних.

5. **Очищення буфера обміну**: Після копіювання вмісту (включаючи зашифрований) в буфер обміну — дані залишаються в буфері необмежено довго. Автоматичне очищення не реалізовано.

6. **Мультимоніторна конфігурація**: Захист від «вікна за межами екрана» використовує жорстко задані пороги (-1000..10000), що може бути недостатнім для великих мультимоніторних конфігурацій.

7. **Конфлікт мови нативних діалогів та інтерфейсу**: Мова нативних діалогів ОС (пошкоджена база, налаштування, трей) визначається при старті і не змінюється динамічно. Мова інтерфейсу може бути змінена без перезапуску. Після зміни мови в налаштуваннях — пункти трею залишаються попередньою мовою до перезапуску.

8. **Поведінка при повному диску**: Не визначена поведінка при неможливості запису в базу або файл налаштувань через брак місця на диску.

9. **Unicode-підтримка в назвах сніпетів**: Не задокументовано, чи обмеження 3–50 символів рахує Unicode code points чи байти. Реалізація рахує символи (characters), але поведінка з емоджі та складними символами Unicode не специфікована.

10. **Розбіжність одиниці виміру поля «вміст» (символи vs байти)**: У вимогах до створення/редагування обмеження вказано в символах (1–65 536), а база даних обмежує поле в байтах (≤65 536 байт). Для мультибайтового тексту (кирилиця — 2 байти/символ у UTF-8) ефективний ліміт у символах може бути значно меншим, ніж 65 536.

11. **Розширення зашифрованого вмісту**: Шифрування додає salt (16 байт) + nonce (12 байт) + GCM overhead, після чого все кодується в base64 (~33% розширення). Для великого відкритого тексту зашифрований результат може перевищити ліміт бази даних. Ефективний максимальний розмір відкритого тексту для зашифрованих сніпетів ≈ 48 000 байт.

12. **Таймінг анімації зникнення Toast**: CSS-анімація fade-out починається через 2 секунди для всіх toast незалежно від їхньої тривалості. Для 5-секундних toast (попередження) це означає, що toast стає невидимим після ~2.3 секунди, хоча DOM-елемент існує ще 2.7 секунди.

13. **Атрибут `lang` HTML-документа**: Атрибут `<html lang>` не оновлюється динамічно при зміні мови інтерфейсу. Screen readers використовують цей атрибут для вибору голосового синтезатора, що може призводити до некоректного озвучення при невідповідності.

14. **Плюралізація рядків screen reader**: Рядок підрахунку результатів завжди використовує множинну форму («N snippets» / «N сніпетів») незалежно від кількості. Для count=1 це граматично некоректно в англійській.

## 12. Стек технологій

### 12.1 Огляд архітектурного рішення

QuickSnippets будується на архітектурі **Tauri v2** — фреймворку, що поєднує нативний Rust-backend з веб-технологіями для інтерфейсу. Ця модель повністю відповідає ключовим вимогам продукту: портативність без інсталяції, безпечне шифрування в пам’яті та мінімальний розмір дистрибутива.

| Критерій | Значення |
|----------|-----------|
| Фреймворк | Tauri v2 (стабільний реліз) |
| Backend мова | Rust (edition 2021) |
| Frontend мова | TypeScript 5.x |
| UI бібліотека | React 19 |
| Цільова ОС | Windows 10+ (x86-64) |
| WebView рушій | WebView2 (Chromium, вбудований в Windows 10+) |
| Розмір дистрибутива | ~10–15 MB (.exe, без інсталятора) |
| Споживання RAM | ~30–50 MB (idle) |

### 12.2 Backend (Rust / src-tauri)

#### 12.2.1 Ядро фреймворку

Tauri v2 виступає оркестратором між WebView та нативними системними API. Усі чутливі операції (шифрування, буфер обміну, база даних) виконуються виключно в Rust-процесі та ніколи не передають розшифровані дані в інтерфейс.

| Crate | Версія | Призначення | Обгрунтування |
|-------|--------|--------------|-----------------|
| `tauri` | 2.x | Фреймворк, lifecycle, IPC | Офіційний реліз; WebView2 на Windows без додаткових залежностей |
| `tauri-plugin-global-shortcut` | 2.x | Глобальна гаряча клавіша | Офіційний плагін; graceful fallback при конфлікті |
| `tauri-plugin-clipboard-manager` | 2.x | Буфер обміну (write-only з backend) | Копіювання без передачі вмісту в UI |
| `tauri-plugin-autostart` | 2.x | Автозапуск через реєстр Windows | Офіційний плагін; повертає помилку в UI при збої |
| `tauri-plugin-single-instance` | 2.x | Single-instance lock | При повторному запуску — фокус на існуючому вікні |
| `tauri-plugin-dialog` | 2.x | Нативні діалоги ОС | Пошкоджена БД / налаштування; локалізовані при старті |

#### 12.2.2 База даних

| Crate | Версія | Призначення | Обгрунтування |
|-------|--------|--------------|-----------------|
| `rusqlite` | 0.32 | SQLite — CRUD сніпетів | Пряме керування шляхом до файлу — критично для портативності |
| feature `"bundled"` | — | SQLite вкомпільований у .exe | Нуль зовнішніх DLL-залежностей |

> **Портативний шлях до файлів:** шлях визначається через `std::env::current_exe().parent()` — файли `snippets.db` і `settings.json` завжди знаходяться поруч з `.exe`. Стандартний `AppConfig` фреймворку (`AppData\Roaming`) навмисно не використовується.

#### 12.2.3 Шифрування

| Crate | Версія | Призначення | Обгрунтування |
|-------|--------|--------------|-----------------|
| `aes-gcm` | 0.10 | AES-256-GCM шифрування/дешифрування | Аутентифіковане шифрування; невірний пароль → `AeadError` |
| `zeroize` | 1.x | Гарантоване очищення ключів та plaintext з пам’яті | Захист від витоку через swap/dump; виконується після кожної операції |
| `rand` | 0.8 | Генерація криптографічного salt (16 байт) та nonce (12 байт) | CSPRNG через `OsRng` |
| `pbkdf2` | 0.12 | Деривація ключа з пароля | 100 000 ітерацій PBKDF2-HMAC-SHA256; унікальний salt на кожен сніпет |
| `sha2` | 0.10 | HMAC для PBKDF2 | Транзитивна залежність; явно вказана для контролю версій |

> **Формат зберігання:** `base64(salt[16] || nonce[12] || ciphertext || GCM-тег[16])`. Розшифрований вміст обнуляється через `zeroize` одразу після копіювання в буфер обміну — ще до повернення відповіді в UI.

#### 12.2.4 Налаштування

| Crate | Версія | Призначення |
|-------|--------|----------|
| `serde` | 1.x | Серіалізація / десеріалізація структур налаштувань |
| `serde_json` | 1.x | Читання та запис `settings.json` поруч з `.exe` |

### 12.3 Frontend (TypeScript / src)

#### 12.3.1 Збирач та середовище

| Пакет | Версія | Призначення | Обгрунтування |
|-------|--------|------------|----------------|
| `vite` | 6.x | Bundler, HMR, dev-server | Офіційно підтримується Tauri; найшвидша збірка |

#### 12.3.2 UI та стилі

| Пакет | Версія | Призначення | Обгрунтування |
|-------|--------|------------|----------------|
| `react` | 19.x | UI бібліотека | Hooks, Concurrent Mode; зрілий a11y-ecosystem |
| CSS Modules | (вбудовано у Vite) | Ізольовані стилі компонентів | Без runtime-overhead; повний контроль над `:focus-visible` та ARIA-стилями |

> **Tailwind CSS навмисно не обрано:** `:focus-visible`, ARIA-стани та анімації toast потребують точного CSS-контролю, який CSS Modules забезпечує без конфліктів із утилітарними класами.

#### 12.3.3 Fuzzy пошук

Алгоритм пошуку реалізований повністю на Rust у backend (команда `search_snippets`). Frontend надсилає рядок запиту та отримує масив результатів з полями: `id`, `title`, `score`, `matched_positions`. Розрахунок виконується на backend з таких причин:

- Алгоритм специфікований в PRD детально (AND-логіка, fallback-розбивка, score −0) — жодна готова JS-бібліотека не відповідає точно
- Backend має прямий доступ до бази без IPC-round-trip на кожен запис
- Debounce 100 мс обробляється на frontend (`useDebounce` hook) — backend отримує лише фінальний запит

### 12.4 Інтернаціоналізація (i18n)

Власна мінімалістична система перекладів без зовнішніх залежностей (i18next та аналоги навмисно не використовуються).

| Аспект | Рішення |
|--------|----------|
| Структура | Один TypeScript-файл з об’єктом `translations: Record<LangCode, TranslationMap>` |
| Тип мов | `LangCode = 'en' \| 'uk'` (union — додавання нової мови потребує лише нового ключа) |
| Параметризовані рядки | Функції-шаблони: `(n: number) => string` для плюралізації та підстановки значень |
| Визначення мови | 1) `settings.json` → 2) системна локаль Windows → 3) fallback `'en'` |
| Динамічне перемикання | React Context (`LanguageContext`); зміна мови — `setLanguage()` → миттєве оновлення всього UI без перезапуску |
| Нативні діалоги ОС | Мова визначається один раз при старті та передається в Rust через стан фреймворку — не змінюється динамічно |

> **Додавання нової мови** (наприклад, `'pl'`): 1) додати ключ `'pl'` в `translations.ts`; 2) додати `'pl'` до `LangCode`; 3) TypeScript перевірить повноту перекладу на етапі компіляції завдяки типу `Record<LangCode, TranslationMap>`.

| Збірка | `tauri build` → `target/release/QuickSnippets.exe` (сирий portable `.exe`) |
| Інсталятор | Не потрібен — `.exe` запускається напрямо |
| WebView2 | Вбудований в Windows 10 21H2+ (KB5008212). Не потребує окремого встановлення |
| Перевірка WebView2 | При старті — перевірка наявності WebView2 runtime; якщо відсутній — нативний діалог з посиланням на завантаження |
| Файли даних | `snippets.db` та `settings.json` — у тій самій директорії, що й `.exe` |
| Перенесення між ПК | Достатньо скопіювати директорію з `.exe` та `.db`/`.json` файлами |
